# 6. Hook launchers and binary location

- Status: Accepted
- Date: 2026-10-15

## Context

A plugin declares its hooks and MCP servers once, in `hooks/hooks.json` and `.mcp.json`, for every operating system. Claude Code has no per-platform condition for them. The `wizard` binary is not shipped in the plugin (see [ADR 0002](0002-single-rust-binary-with-cli-and-mcp-modes.md)): it is downloaded on first use for the current platform.

How Claude Code runs a command hook, measured on Claude Code 2.1.300:

- **Shell form** (a `command` string): `sh -c` on Linux and macOS. On Windows, Git Bash when it is installed, otherwise `powershell.exe -NoProfile -NonInteractive -ExecutionPolicy Bypass -Command`. Git Bash is optional on Windows.
- **Exec form** (`command` and `args`): the executable is spawned directly, without a shell. On Windows, an absolute path without extension resolves to the `.exe` file, so one path works on every platform.

Hooks run on every prompt and around tool calls, so spawning a shell for each of them would cost tens to hundreds of milliseconds on Windows, against a 50 ms budget.

## Decision

- **Binary location.** The current binary lives at a stable path, `${CLAUDE_PLUGIN_DATA}/bin/wizard` (`wizard.exe` on Windows). `${CLAUDE_PLUGIN_DATA}` survives plugin updates. Downloaded versions are kept beside it for rollback.
- **Every hook except `SessionStart`, and the MCP server,** use the exec form on that stable path, with no shell.
- **`SessionStart`** uses a shell-form launcher that is valid in sh, bash and PowerShell:

  ```
  cd "${CLAUDE_PLUGIN_ROOT}/scripts"; . ./session-start
  ```

  sh and bash source the POSIX script `session-start`. PowerShell resolves `./session-start` to `session-start.ps1`. The launcher installs or updates the binary when needed, then hands the event to it on standard input.
- **Version handshake.** The binary compares its own version with the plugin version and stays inert when they differ, until the launcher installs the matching binary.
- **Event dispatch.** The binary reads the event name from the JSON it receives, so every hook uses the same command.

The download lands with the bootstrap task (P0-10) and the handshake with the version check task (IU-05). Until then, the launcher only runs a binary that is already installed.

## Consequences

- Hooks other than `SessionStart` never pay for a shell, on any platform.
- The same `hooks.json` works on Linux, macOS and Windows, with or without Git Bash.
- Until the first download completes, exec-form hooks cannot start, and Claude Code shows a non-blocking hook error. The launcher downloads synchronously on the first `SessionStart` to keep that window short.
- Claude Code passes `CLAUDE_PLUGIN_ROOT` to sh and bash as an environment variable and substitutes it for PowerShell, so the path is double-quoted: single quotes would keep sh and bash from expanding it. A plugin path containing a double quote breaks the launcher command; plugin paths are generated by Claude Code under the user's home directory, which makes this rare.
- The launcher is covered by integration tests in every shell available on the CI runners.
